StrataOS 0.15.2: security fixes for file versions, subtitles, the photo editor and the HDMI kiosk, plus fixes that make the 0.15 features work as announced: WiFi that applies and rolls back, CalDAV/CardDAV usable by real phones and computers, a cinema library that finds your videos and respects who may see them, and a much faster assistant with small local models.

## Installation

- **Already on 0.15.1 or older**: **Updates → Update StrataOS** in the web interface. Update soon: this release fixes security issues.
- New installs: `amd64` / `arm64` ISO, `strataos-0.15.2-raspberrypi.img.xz`, or `sudo apt install ./strataos_0.15.2_<arch>.deb`.
- **Calendars and contacts**: devices set up with the address of the collection itself (`…/caldav/<account>/default/`) must be set up again with `https://<nas>:7443/caldav/` and `https://<nas>:7443/carddav/` (see the guide). Your events and contacts are kept and converted at the first connection.

## Security fixes

- **File versions**: restoring an earlier version of a file could be made to overwrite any file of the system (for example the password file) through a symbolic link planted next to it. The restore now writes only inside the shared folder, through a new temporary file, and keeps the file's permissions and owner.
- **Subtitles and transcription**:
  - a subtitle file next to a video could be a link to a system file (its content was shown in the player) or to an endless device (the NAS ran out of memory). Subtitles are now read inside the shared folder only, as regular files of at most 5 MB;
  - fetched subtitles and transcriptions could be written through a planted link as administrator. They are now written inside the shared folder only, owned like your other files.
- **Photo editor**: it followed links out of the shared folder. It now stays inside it, and refuses pictures over 100 megapixels before decoding them.
- **HDMI output**:
  - the TV's browser was signed in with full administrator read access to every file. It now acts, read-only, as the account an administrator chooses for the TV, on the cinema and video playback only (nothing is shown until an account is chosen);
  - its secret was visible to every local user in the browser's command line, the browser ran as administrator with a predictable profile folder, and the remote-control channel took the secret in its address. The browser now runs under its own unprivileged account (`strata-kiosk`, created by the update) with a private folder, the secret is in a file only that account can read, and the remote channel receives it privately;
  - the TV remote of the web app is for administrators and the accounts they allow.
- **Cinema**: every account saw the videos of every shared folder (titles, posters, watch lists). Each account now only sees the videos of the folders it can read.
- **Family profiles** were applied by the browser only and on the TMDB vote average. They are now enforced by the NAS, on the age certification of each film or series (unrated videos are hidden under a limit), for the accounts an administrator assigns; these accounts cannot change them.
- **Shared albums**: a recipient kept seeing a photo after its owner lost access to it. Album photos now follow the owner's current access.
- **Errors from TMDB** could show the TMDB API key. They no longer do.
- **OpenSubtitles**: the download address given by the service is now only fetched over HTTPS from a public address.
- **Migration**: a saved password is no longer sent to a different server after the address is changed; line breaks in user names and passwords are refused; mirroring (deleting what the source no longer has) is only allowed into a folder of a share, never into the whole share.
- **Web app**: the offline cache could keep file, calendar and contact answers. It now keeps only the interface, and signing out clears it.

## Fixed

**WiFi**
- The WiFi settings were written where Debian's WiFi service never reads them, so they never applied, and a running connection was not restarted. Both are fixed.
- A wrong password applied on trial is now really rolled back: the NAS reconnects to the previous network, or disconnects when there was none.
- Passwords with a quote, a backslash or exactly 32 characters were written wrongly; they are now stored as the WPA key itself. Tested with a simulated access point.

**Calendars and contacts (CalDAV, CardDAV)**
- Real clients (iPhone, DAVx⁵, Thunderbird) could not use them: the protocol is now handled by the go-webdav library (MIT), with standard discovery, full calendar objects with their time zones, the names devices choose, version tags that prevent silent overwrites, and safe writes.

**Cinema**
- The library stayed empty on normal installations: every shared folder of a mounted volume is now scanned.
- A scan interrupted by a restart left the library "scanning" forever.
- Searching subtitles by file now uses the real OpenSubtitles file hash, so it finds matches.
- Resume points are only kept for videos of your library (500 per account); watch lists are limited per account (50) instead of 100 for the whole NAS.

**Assistant**
- With a local Ollama model, turning **Thinking** off did not stop the model from reasoning: it now really does (measured with qwen3 0.6B: the first word in a fraction of a second instead of 5 to 8 seconds).
- **Light mode** (automatic for local models of 4 billion parameters or fewer): a short prompt and only the tools that read the NAS, about three times faster on a NAS processor.
- Continuing an answer after confirming a web page failed with a ChatGPT account.
- Two refreshes of a ChatGPT session at the same time could sign the account out.
- The **ChatGPT account** sign-in is now marked experimental (it relies on the client of OpenAI's Codex command-line tool, which OpenAI may block). The **Mistral account** sign-in is removed, as its addresses could not be confirmed: use a Mistral API key.

**Photos and files**
- The photo editor dropped the date taken and the place of a photo: EXIF data is now kept, the picture is turned upright, and **crop** is added, as announced.
- The automatic photo upload of the web app overwrote a photo of the same name. It now skips a photo already sent and stores another one as "name (2).jpg".

**Notifications, apps and power**
- Webhooks and ntfy can again post to an app running on the NAS itself, as before 0.15.
- An app domain pointing to an `https` address of the local network can accept a self-signed certificate (an option of the domain).
- A container that restarted once was reported as "crashing" when it had crashed long ago: restarts are now counted over the last hour, and crash alerts no longer copy log lines to mail, ntfy or webhooks.
- A new spin-down delay was not applied to disks that were asleep at the time.
- Sign-in alerts: a browser update is no longer a "new device", and up to 100 devices are remembered per account.

**Features not available yet, now said plainly**
- Speech-to-text needs whisper.cpp and its model installed by hand (see the guide); the button says so. The surveillance object labels are not available (use the Frigate engine). The roadmap no longer ticks the import from Google Photos and Dropbox, the sign-in with Mistral, DeepSeek, Kimi and Claude accounts, photos and Bluetooth remotes on the TV, and the app icon badge.
- The user guide (English and French) has new sections on the cinema, the HDMI output, calendars and contacts, subtitles, the ChatGPT sign-in, watched NAS, browser notifications and the web app's photo upload.
