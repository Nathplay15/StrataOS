StrataOS 0.9.0: Ceph storage and a cluster of NAS for virtual machines, with live migration and automatic restart on another NAS.

## Installation

- **PC / server**: `amd64` ISO (BIOS and UEFI). **UEFI ARM board**: `arm64` ISO.
- **Raspberry Pi 3 / 4 / 400 / 5 / CM4 / CM5**: `strataos-0.9.0-raspberrypi.img.xz`.
- **Existing Debian 13 system**: `sudo apt install ./strataos_0.9.0_<arch>.deb`.
- **Already on 0.8 or older**: **Updates → Update StrataOS** in the web interface.
- **Android phone**: `strataos-0.9.0.apk`. **Computer**: StrataOS Sync, `strataos-sync-0.9.0-*` (Windows, macOS, Linux).

## What's new

**Ceph**
- Create a Ceph cluster between 3 StrataOS NAS or more from the web interface (Storage → Ceph): monitors, managers and disks (OSDs) set up by StrataOS from the Debian packages, an RBD pool and/or a CephFS file system, 3 copies by default. Add or remove a NAS or a disk safely, replace a failed disk, maintenance mode.
- A dashboard with the health explained in plain words, capacity, disks, recovery progress and throughput, and notifications when the health changes.
- Use Ceph as storage on a NAS, from its own cluster or an existing external one: a CephFS volume (shared folders work on it), an RBD volume, and Ceph as the disk storage of virtual machines.
- Install the "Ceph" component from Settings → Components. A Ceph cluster is worth it with 3 NAS or more, a fast network (10 GbE recommended) and enough memory (about 1 GB per disk).

**Cluster of NAS for virtual machines**
- The NAS of a Ceph cluster manage their virtual machines together (Virtual machines → Cluster): every VM and container of every NAS in one list, with its console.
- **Live migration** of a VM to another NAS, without stopping it (with its disks on Ceph; with local disks the disks are copied, more slowly). Containers move with a short stop.
- **High availability**: a VM marked "HA" restarts on another NAS when its NAS fails. It needs 3 NAS (a majority decides), and the failed NAS is cut off from the disks before the VM restarts elsewhere, so a VM never runs twice.
- **Maintenance mode**: a NAS hands its VMs over to the others before an update or a restart. Grouped updates of the Multi-NAS Console never restart two NAS of a cluster at once, and move their VMs away first.

**Also**
- Fixed: a virtual machine on a network bridge had no network when Docker was installed.
- Fixed: the desktop sync app could stay stuck when it was quit, or when its folders changed, during a synchronization.
